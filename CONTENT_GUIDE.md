# Управление контентом FULL CORE

## Демонстрационный режим

По вашему запросу включён `demoMode: true` в `src/data/site.ts`. Пять примеров в `src/data/demo.ts` показывают заполненный сайт с фотографиями, галереями и рабочими локальными видео. Все отмечены Sample / Preview; это не ваши проекты. Источники и лицензии — `public/media/demo/CREDITS.md`.

Чтобы перейти к реальному портфолио: заполните черновики в `src/data/projects.ts`, поставьте им `status: "published"`, затем переключите `demoMode: false`. Это одновременно уберёт демо-кейсы, баннер . Ваш собственный `site.showreel`, если задан, будет показан вместо демо. После переключения можно удалить `public/media/demo/` и пересобрать сайт. Не отправляйте демо-версию как подтверждение авторства работ.

## Личная информация

Редактируйте `src/data/site.ts`: бренд, tagline, subtitle, location, about, approach, tools, disciplines, ссылки, email, available и availability. Пустые email, portrait и cv не создают неработающих кнопок. `url` — реальный HTTPS-адрес сайта, включая подпапку при необходимости. На GitHub Pages адрес автоматически задаёт workflow через VITE_SITE_URL. После его добавления пересоберите сайт.

`public/core-study.svg` — абстрактная графика интерфейса, не пример вашей работы. Для showreel задайте `showreel` как объект Media (см. ниже). Он заменит графику и будет запускаться только по клику. Для фотографии: `portrait: '/media/portrait.webp'`. Для CV: `cv: '/media/full-core-cv.pdf'`.

## Быстрое добавление проекта

1. Загрузите принадлежащее вам видео на YouTube/Vimeo. Разрешите встраивание; YouTube может быть Unlisted, но не Private.
2. Подготовьте обложку WebP/AVIF (обычно до 1600 px по длинной стороне, желательно 100–250 KB).
3. Положите её в `public/media/my-project.webp`.
4. В `src/data/projects.ts` заполните существующий черновик или добавьте объект в `projects`:

```ts
{
  id: 'your-unique-id',
  slug: 'your-project-slug',
  title: 'Your confirmed project title',
  category: 'motion',
  status: 'published',
  // year: 2026, // Только подтверждённый год
  description: 'A short, factual description of the work.',
  role: ['Motion design', 'Editing'], // Только реальные роли
  tools: ['After Effects'],
  coverImage: '/media/my-project.webp',
  coverAlt: 'Describe the actual image',
  coverAspectRatio: '16/9',
  featured: true,
  featuredOrder: 1,
  media: [{
    id: 'main-film',
    type: 'youtube',
    url: 'REPLACE_WITH_REAL_YOUTUBE_ID',
    thumbnail: '/media/my-project.webp',
    aspectRatio: '16/9',
    caption: 'Optional factual caption',
  }],
}
```

Это образец структуры: замените URL и текст, прежде чем публиковать. Сборка отклоняет опубликованные проекты без медиа или с некорректными ссылками провайдера.

5. `npm run build` → загрузите содержимое `dist/` или отправьте изменения в подключённый GitHub.

## Форматы медиа

- YouTube: `type: 'youtube'`, URL watch/shorts/youtu.be или 11-символьный ID.
- Vimeo: `type: 'vimeo'`, URL или числовой ID. Unlisted URL с privacy hash поддерживается. Проверьте разрешения домена в Vimeo.
- Видео-файл: `type: 'localVideo'`, `url: '/media/film.mp4'`, желательно MP4 H.264/AAC, отдельная обложка. Скачивание начинается после Play. Большие ролики лучше размещать на YouTube/Vimeo.
- Фото: `type: 'image'`, `url: '/media/image.webp'`, `alt: 'Accurate image description'`. Укажите aspectRatio, чтобы зарезервировать место. Изображения загружаются лениво, увеличение — по клику, закрытие — кнопкой или Escape.

Все объекты имеют уникальный `id` внутри media. Соотношения: `'16/9'`, `'9/16'`, `'1/1'`, `'4/3'`. Вертикальные видео ограничены по ширине, не обрезаются. Добавьте 2–3 Media в один chair campaign, а не три отдельных проекта. Первый объект — главный материал. Остальные выводятся ниже; опциональные role, tools, process, credits и externalLinks отображаются только при наличии. `client`, `tags`, `subtitle`, `year` также необязательны.

Для локальных файлов используется путь **без public**: `/media/file.webp`. Не кладите секретные материалы в public: даже черновик не делает лежащий там файл приватным.

## Порядок, фильтры и скрытие

- Название: `title`. Slug — постоянный URL; изменение требует редиректа со старого адреса.
- Главная: `featured: true`, порядок — `featuredOrder` по возрастанию.
- Каталог: порядок объектов в массиве. Первоначально 12 карточек, затем Load more.
- Скрыть: `status: 'draft'`. Это убирает страницу из следующей сборки и sitemap. Удалите старую директорию проекта с ручного хостинга, если она осталась от прежней версии.
- Новая категория: добавьте `{ id: 'your-id', label: 'Your label' }` в `categories`, используйте ID в проектах. Не добавляйте AI-категорию до появления реальных работ.
- Пустая категория показывает честное пустое состояние. Шесть исходных записей — рабочие группы для подготовки, не готовые кейсы.

## Перед отправкой рекрутеру

Проверьте фактическое авторство, название, роли, разрешение на публикацию и рабочие ссылки. Добавьте лучшие Motion / Studio / Film кейсы, обложки и контакт. Проверьте плееры на телефоне и на реальном домене: ограничения площадок, регионов или браузера нельзя проверить только сборкой. При необходимости включите субтитры в YouTube/Vimeo, для локального видео подготовьте доступную версию с субтитрами. Не приписывайте AI, показатели, награды или участие в чужих работах.

## Новая структура разделов

Основные страницы: HOME, VIDEO, MOTION, 3D / VFX, DESIGN, ABOUT, CONTACT. Данные и старые URL `/work/slug` сохранены.

- `category: 'commercial'` или `'film'` → VIDEO.
- `category: 'motion'` → MOTION; добавьте минимум одно видео.
- `category: 'design'` → DESIGN; добавьте изображения с alt. На странице раздела выводятся только изображения, до четырёх на проект, остальные доступны внутри кейса.
- `category: '3d-vfx'` → 3D / VFX; поддерживаются изображения и видео.

Для VIDEO задайте `videoType`: `'studio-commercials'`, `'product-reviews'`, `'reels-ads'` или `'personal-films'`. Без значения старые commercial-проекты считаются studio-commercials, film — personal-films. Черновики уже имеют подходящие значения. Для кампании кресел добавляйте несколько видео в один массив media.

Selected Works на главной показывает только реальные опубликованные проекты с featured:true, до четырёх, в порядке featuredOrder. Демо туда никогда не попадает. Демопримеры открываются через категории. Главная не использует демо-showreel; реальный site.showreel по-прежнему поддерживается и раскрывается по кнопке.

Когда demoMode:false, пустые разделы скрыты из меню, плиток и статической сборки. Для намеренной публикации пустых страниц включите publishEmptyDisciplines:true. В demoMode все четыре страницы доступны с честным empty state. Дополнительные дисциплины без согласования не добавлять.

## Русский и казахский языки

Переключатель EN / RU / KZ стоит после Contact. Английский используется по умолчанию; выбор сохраняется в браузере. Технический код казахского — kk, не kz. Строки интерфейса хранятся в src/i18n/messages.ts. Сохраняйте файлы как UTF-8 без BOM, не используйте escape-последовательности вместо букв.

Для нового проекта исходные английские поля остаются основными. Добавьте необязательное поле translations:

```ts
translations: {
  ru: { title: 'Название проекта', description: 'Описание проекта', role: ['Монтаж'] },
  kk: { title: 'Жоба атауы', description: 'Жоба сипаттамасы', role: ['Монтаж'] },
},
```

Поддерживаются title, subtitle, description, role, process, credits, coverAlt. У каждого Media отдельно можно задать translations: { ru: { caption: 'Подпись', alt: 'Описание изображения' }, kk: { caption: 'Қолтаңба', alt: 'Сурет сипаттамасы' } }. Названия программ и брендов оставляйте исходными. Отсутствующий перевод нового контента не угадывается: отображается исходный английский текст.

Язык не изменяет URL и фильтры. Перевод выполняется локально, без внешних API. Статический HTML и социальные превью остаются английскими; после выбора языка обновляются интерфейс, lang документа, title и description в браузере. Отдельных индексируемых ru/kk URL в этой версии нет.

## Музыка: добавление треков

Раздел MUSIC находится по адресу `/music` и доступен из основного меню. Список — `src/data/tracks.ts`. Пока он пуст, сайт честно показывает подготовку авторских треков, без фиктивных песен и неработающих Play-кнопок.

1. Экспортируйте готовый трек в MP3 или AAC/M4A. MP3 — наиболее простой вариант для разных браузеров. Для сайта не обязательно загружать тяжёлый исходный WAV.
2. Положите файл в `public/media/music/your-track.mp3`, обложку — туда же (рекомендуется квадратный WebP).
3. Добавьте объект в tracks. Пример структуры, не готовая запись:

```ts
{
  id: 'your-track',
  title: 'Your actual track title',
  status: 'published',
  src: '/media/music/your-track.mp3',
  artwork: '/media/music/your-cover.webp', // Необязательно
  // year: 2026, // Только реальный год
  description: 'Optional short description.',
  credits: 'Optional factual credits.',
  translations: {
    ru: { title: 'Название трека', description: 'Описание' },
    kk: { title: 'Трек атауы', description: 'Сипаттама' },
  },
  externalLinks: [], // Добавляйте только настоящие ссылки на релиз
}
```

4. Пересоберите сайт. `status: 'draft'` скрывает трек. Порядок объектов задаёт порядок списка.

Можно использовать прямой HTTPS-адрес аудиофайла, если сервер разрешает его воспроизведение браузером. Страница SoundCloud/Spotify не является прямым MP3: такие ссылки добавляйте в externalLinks. Формат/кодек и разрешения внешнего сервера проверяйте после публикации. Не загружайте файлы более 100 MB в обычный GitHub-репозиторий; лучше использовать сжатый web-экспорт.

Все треки используют один HTML-аудиоплеер. До нажатия Play аудио не загружается. В нём есть штатные перемотка и регулировка громкости (на телефонах — системная), Play/Pause и кнопки предыдущего/следующего трека. Автоматического запуска следующей песни нет. На MUSIC плеер закреплён снизу и остаётся доступным при прокрутке. Высота панели автоматически учитывается в отступе страницы, включая safe area телефона. При уходе с MUSIC музыка останавливается, панель скрывается.

По явному запросу для тестирования добавлены три процедурных музыкальных демофрагмента (около 24 секунд каждый). Это не треки FULL CORE. Их данные — src/data/demoTracks.ts, файлы — public/media/music/demo/. Записи созданы без чужих аудиосемплов; происхождение описано в CREDITS.md рядом с файлами. Пока сохраняете демо в списке, оставляйте поле demo:true и не называйте их собственными релизами.

## Обложки и закреплённый плеер

У каждого демотрека теперь есть своя временная обложка: ambient-cover.webp, pulse-cover.webp, glass-cover.webp в public/media/music/demo/. Эти абстрактные иллюстрации сгенерированы для демонстрации интерфейса, не являются вашими релизами или работами портфолио.

Чтобы заменить обложку своего трека:

1. Подготовьте квадратный WebP или JPEG, желательно 512 × 512 или 1024 × 1024 пикселей.
2. Положите файл в public/media/music/.
3. В объекте трека задайте `artwork: '/media/music/my-cover.webp'`. Для временных примеров редактируйте demoTracks.ts; собственную музыку добавляйте в tracks.ts.
4. Выполните npm run build и опубликуйте изменения.

Одна и та же обложка автоматически появляется в списке и в закреплённой нижней панели при выборе трека. Поле artwork остаётся необязательным: без него выводится нейтральный значок диска. Аудио не загружается до Play. Закрепление действует только в разделе Music; воспроизведение останавливается при переходе на другую страницу.

На первом экране теперь упомянут музыкальный продакшен. Заголовок и перечень направлений редактируются через site.tagline и site.subtitle; их русские и казахские версии — в src/i18n/messages.ts.
